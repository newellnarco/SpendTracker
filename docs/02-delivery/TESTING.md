# Testing strategy

## Pyramid

| Level | Scope | Tooling | Runs |
| --- | --- | --- | --- |
| Unit | pricer math, rate lookup, validators, cursor logic, redaction | pytest, hypothesis | every push |
| Contract (adapter conformance) | each adapter: fixtures → expected events, stability, no I/O in `normalize` | `st adapter test`, respx for HTTP | every push, nightly CT |
| Integration | hook script → spool → ingest → DB → pricer → view | pytest with a temp DB and real hook scripts | every push |
| Data invariants | SQL assertions over a populated DB | pytest + sqlite3 | every push and nightly against a synthetic 4M-row DB |
| UI | one Playwright smoke per page; API contract tests | Playwright (pre-installed Chromium), schemathesis for `/api/v1` | every push (Linux), nightly (matrix) |
| Migration | apply every migration from every historical snapshot | pytest, snapshots in `tests/schema_snapshots/` | every push, nightly |
| Performance | view latency at 4M events; rollup build at 5M | pytest-benchmark | nightly, warn on regression > 20 % |
| Install | build wheel, install with pipx on macOS, Linux, Windows, run `st doctor` | GitHub Actions matrix | release and nightly |
| Live vendor (optional) | read-only calls to vendor APIs with a personal token, assert response shape | pytest with `--live`, skipped without tokens | nightly on a runner that has tokens |

## Invariants (data tests)

| Invariant | Query sketch |
| --- | --- |
| Every automatic event has a `source_ref` | `SELECT COUNT(*) FROM usage_event WHERE source IN ('hook','otlp','api','transcript') AND source_ref IS NULL` = 0 |
| No unknown measures | `usage_event.measure_id` ⊆ `measure.measure_id` (FK) |
| Cost conservation per subscription period | `Σ allocated + Σ idle = fee` within 1 micro per period |
| Effective ≤ list for covered events in aggregate | per subscription period, unless overage exists |
| No cost line without an event except `idle` | `cost_line.event_id IS NULL ⇒ cost_kind = 'idle'` |
| Daily view equals event sum | `Σ v_daily_cost.effective = Σ v_event_cost.effective` |
| Export round-trip | export → import into fresh DB → same event count and same per-day sums |
| Re-price idempotent | run pricer twice → identical `cost_line` content hash |

## Fixtures

- `tests/fixtures/<adapter>/raw/*.json`: recorded payloads with secrets and content removed.
- `tests/fixtures/<adapter>/expected/*.jsonl`: expected events, reviewed by a human once.
- `tests/fixtures/db/synthetic_4m.sql.gz`: generated by `tests/gen_synthetic.py` with a fixed seed.
- `tests/fixtures/claude-code/`: hook stdin payloads per event type; OTLP JSON for `api_request`,
  `tool_result`, cumulative metrics; a transcript JSONL with 20 assistant messages and one sub-agent.
- Golden cost example from COST-MODEL §4 as `tests/golden/claude_max_usage_share.yaml`.

Updating an expected file requires a commit message explaining why the expectation changed.

## Continuous testing (CT)

CT is the scheduled part: it runs without a code push and catches drift in vendors, data and
environment.

| Job | Schedule | What it checks |
| --- | --- | --- |
| `ct-replay` | nightly | All adapter fixtures against the current main build |
| `ct-migrations` | nightly | Every schema snapshot migrates to head; populated-DB migration keeps sums |
| `ct-perf` | nightly | View and rollup benchmarks |
| `ct-live` | nightly (opt-in runner) | Vendor endpoint shapes; rate card staleness |
| `ct-rollup` | weekly (rollup repo) | Full rebuild from scratch equals incremental build |
| `ct-install` | nightly | Fresh install on three OSes |

Failures open an issue labelled `ct` with the job log link; the next phase's step 1 includes reading
open `ct` issues.

## Local commands

```
uv run pytest                      # unit + integration + invariants
uv run pytest -m ui                # Playwright smoke
st adapter test --all              # conformance suite
uv run pytest --live               # vendor checks (needs tokens in env)
```

## Test data hygiene

- No real tokens, emails, hostnames or prompt text in fixtures. A pre-commit hook scans for
  token-like strings and email patterns.
- Synthetic data uses fake model names only where pricing is not under test; pricing tests use
  real model ids with the seed rate cards.
